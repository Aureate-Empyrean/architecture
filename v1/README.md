# GitHub backlog and capability traceability

[All open organization Issues](https://github.com/issues?q=org%3AAureate-Empyrean%20is%3Aissue%20is%3Aopen) · [Open V1](https://github.com/issues?q=org%3AAureate-Empyrean%20is%3Aissue%20is%3Aopen%20label%3Aae%3Av1) · [Ready and unassigned V1](https://github.com/issues?q=org%3AAureate-Empyrean%20is%3Aissue%20is%3Aopen%20label%3Aae%3Av1%20label%3Astatus%3Aready%20no%3Aassignee)

GitHub Issues are the authoritative actionable backlog. Independent module repositories own their work; architecture owns ecosystem contracts, cross-repository acceptance and decisions. Read live Issue descriptions, metadata, native dependencies, assignments and comments before execution. This page and local JSON are provenance snapshots, not a second queue.

[BACKLOG_MAP.json](BACKLOG_MAP.json) reconciles all 162 original IDs, all 43 legacy draft aliases and additional findings to canonical Issues or explicit dispositions. It also records the tracked documentation review and retained local-only material. [CAPABILITY_CHECKLIST.csv](CAPABILITY_CHECKLIST.csv) preserves the original evidence: its old `task_coverage` and unchecked acceptance columns are historical, superseded as work tracking by the mapping and live Issues. A broad checklist row can have several independently scoped residuals; identical work is never duplicated just to give each row its own Issue.

Open Issues use exactly one execution state: `ready`, `blocked`, `backlog`, `in-progress` or `review`. Implementation, validation, integration, deployment and production verification remain separate evidence milestones. Future scope is `ae:future`; unresolved inclusion is `ae:scope-undecided`. Neither is eligible for V1 selection. Issue JSON dependency milestones and native blocking edges must agree; closed duplicate/not-planned work does not satisfy acceptance.

Use the [shared agent standard](../AI_AGENT_INSTRUCTIONS.md), [owner workflow](OWNER_AGENT_WORKFLOW.md) and [three provider-agnostic prompt templates](PROMPT_TEMPLATES.md). One assigned Issue is one bounded implementation/review session. Current single-selector discipline remains; no execution runner, Actions, leases or new orchestration service is installed. The [dormant parallel design](future-parallel-automation.md) remains historical design evidence; [its decision Issue](https://github.com/Aureate-Empyrean/architecture/issues/32) owns any future revival.

The [candidate reconciliation](CANDIDATE_RECONCILIATION.json) and [historical workflow verification](WORKFLOW_VERIFICATION_2026-11-10.md) preserve evidence, not live status or current acceptance. Completed Chronos, Lyra and Argus implementation candidates require review/integration evidence; do not recreate their ancestors. Meridian/Atlas external ownership and dirty architecture files require explicit handoff. Private tooling remains paused.

The [migration and documentation review Issue](https://github.com/Aureate-Empyrean/architecture/issues/18) records publication verification and the documentation-only review PR. Merge/deployment/destructive changes and major architecture choices retain their owner-approval boundaries. Historical audits, deployment records and specifications retain unique knowledge; their old TODO sections no longer compete with live Issues.
