# Global Resource Search & References

Status: Proposed for owner review. This document specifies discovery and insertion of existing resources. [Architecture #31](https://github.com/Aureate-Empyrean/architecture/issues/31) retains the separate decision on creating a resource from a picker. [Nexus #13](https://github.com/Aureate-Empyrean/empyrean-nexus/issues/13) owns coordination and the broader search scope decision.

## Decision

Use a module-owned search projection over Module Protocol v1. Nexus brokers queries to enabled providers under existing exact projection grants. Providers search their own data, filter before ranking and limiting, and return a bounded identity and presentation. An embedded module calls Nexus using its server-side module identity after authenticating the user. The browser receives neither module bearer tokens nor resolver keys. The source editor retains an ordinary AE Entity Reference and opens it through the existing resolver and navigation flow.

This extends [the module contract](module-contract.md), [projection queries](projections.md) and [ADR 0011](../decisions/0011-projection-queries.md), [local-first discovery](search-and-discovery.md), [interoperability](interoperability.md), [cross-module references](cross-module-references.md), [stable identity and lifecycle](resource-identity-and-lifecycle.md) and [principal rules](principals-and-permissions.md). Nexus's [Entity References](https://github.com/Aureate-Empyrean/empyrean-nexus/blob/main/docs/cross-module-references.md) and [navigation history](https://github.com/Aureate-Empyrean/empyrean-nexus/blob/main/docs/navigation-history.md) describe the existing wire and host behavior.

| Approach | Benefit | Cost |
| --- | --- | --- |
| Delegation through Nexus, proposed | Fresh owner-side authorization and filtering, existing projection transport, independent module storage and release cycles | Variable provider latency and ranking, temporary gaps when a module is down, bounded fan-out per query |
| Central derived content index | Uniform ranking and pagination, potentially fewer request round trips | Requires an approved feed, per-principal visibility, reliable revocation and deletion/restore handling, and custody of copied metadata. An index could expose stale titles or existence during outages or revocation. |

The existing Nexus relationship index remains rebuildable backlink data. Its entries are insufficient for discovering resources that nobody has linked. Revisit any centralized derived index only after measuring delegation and specifying invalidation and authorization under the interoperability rules. The proposed design uses zero persistent cross-module search cache and zero direct cross-module database reads.

## Provider contract

Proposed optional projection name `resource-search`, using `POST /api/v1/module/projections/query` and existing private `POST /empyrean/v1/projections/<name>` transport, envelope, resolver key and authenticated requester. A provider declares the name it provides. A consumer requires reviewed `projections.read` scopes for exact provider/name pairs, plus separate exact `references.resolve` scopes for candidate types it can use. Apply existing reference create/read scopes for published edges. The eligible-provider list is the intersection of current caller grants and enabled, compatible providers, filtered to types the consumer can resolve. Nexus derives this from registration and verified identity, never from a browser-supplied requester or URL. An ungranted or sensitive provider is invisible.

Existing `link-search` in Chronos and Mnemosyne returns labels to Meridian and records requester label grants while searching. Reuse normalization and owner query code where appropriate. Keep that caller contract compatible. The new named projection isolates the read-only contract from that side effect. A search hit grants zero additional access, changes no provider state and causes no network egress. Resolve separately at insertion/display/open according to current owner policy. An owner may expose fewer resources than the calling human can see in its own module. The reference holder does not acquire the human's wider access or item visibility.

Request query contains `q` and optional `limit`. Include optional type filters only for the provider's advertised referenceable types. Reuse the opaque projection cursor for an explicitly requested next page if supported. Each result has `resource` and `label`. Module and type come from the validated canonical reference and its provider envelope. A result can optionally carry a short plain-text `preview` for that requester; adapters may omit it and the pilot should ship titles only. Existing types, UUIDs and resolver destinations must be used.

```json
{"resource":"nexus:v1:meridian:person:0192a5d3-7c1e-7b2a-9f4e-3d8c1b6a2e10","label":"Example contact"}
```

Validate UUID/type syntax, provider ownership and exact scope before showing an item. Discard malformed rows, mismatched owners, arbitrary navigation targets and unexpected executable markup. Render text as text. The provider authorizes before filtering, ordering, counting or producing cursors. Match normalized case and diacritics, prefer whole-title or prefix matches to token matches, and give rows a stable identity tie-break. Merge identical canonical IDs only, even if labels match. Keep provider groups in stable order and preserve selection by identity across updates.

Start with a trimmed query of 2–100 characters, at most 8 tokens, about 200 ms debounce, 10 results per provider by default and a hard cap of 20. Open at most 4 in-flight provider calls per search and show at most 40 rows total, with a bounded request budget and a provisional 2 s overall UI deadline. Treat these as tunable pilot defaults. Use existing envelope caps and server-side rate limits per caller/session. A query generation ID fences late results. Cancel superseded work where supported, enforce deadlines server-side and ignore obsolete replies. Search terms, results, private IDs and preview content stay out of logs, traces and URLs. Use request-local state cleared on sign-out or permission changes. Recheck authorization for each returned page and on open.

Use independent scoped requests, or an additive Nexus adapter invoking the same per-provider path, so that approved providers can return progressively. A disconnected provider can't hold back successful groups. Show loading while groups are pending, an empty state after successful zero-match completion, a partial-result notice and retry on timeouts/errors for eligible providers, and an unavailable state if no provider could complete. Never show names, counts or states of ungranted providers. No empty-query listing. A narrower query or explicit provider filter is available when results are capped.

## Reference persistence and navigation

Store the canonical `nexus:v1:<module-id>:<resource-type>:<uuid>` identity in the source document's supported reference representation. Resolve the current label separately. A name, preview, provider-specific ID or route never substitutes for the canonical identity. Mnemosyne's current editor is a Markdown textarea. Its pilot should use an explicit round-trippable Markdown representation, for example `[AE reference](nexus:v1:meridian:person:<uuid>)` with a neutral label. Recognize only valid references in supported markup outside literal/code contexts, render via the document's safe preview pipeline and intercept activation through AE navigation. Existing Markdown text and length limits still apply. A successfully pasted structured or Markdown reference preserves identity after validation. Plain-text clipboard fallback uses a neutral label outside AE; portable Markdown/export can preserve identity without private target titles. A pasted reference confers no access. Undo/redo, save conflicts, reload and export preserve whole references, with a readable fallback in plain-text editors. Escaped or unsupported lookalikes remain literal. Keep labels/previews out of persisted reference metadata and fallback text.

Source content is authoritative. If publishing backlinks, apply the source-owned relation and explicit reader policy through the existing references API. The underlying note is the source. Save first, reconcile the unique source-target-relation edges after successful commits, and derive enumeration from committed source state. Removing one of multiple mentions preserves the edge until the last is removed. Retry failed index work idempotently without dropping the note or its token. Notify the editor of a failed note save via its normal revision/dirty-state behavior. The target owner sees backlinks only where existing grants and product policy permit.

On activation, resolve through Nexus with current credentials and exact scope. Only an available reply with an exact owner-provided, validated module-relative destination can be passed to the existing bound-app bridge or host route. Use normal save/leave guards and document/session fencing. The destination independently rechecks authentication and access. Deny URL schemes, foreign origins, path traversal including encoded variants, forged messages and arbitrary search-provided paths. If exact route support is absent, keep the reference unresolved for opening rather than opening an unrelated fallback view. Preserve legacy hosting behavior where exact authenticated navigation is supported.

| Condition | Editor and navigation behavior |
| --- | --- |
| Rename or move within the same owner/type | Same ID. Show fresh authorized label and resolve the current destination. |
| Restore | Same original ID becomes usable again when available. A recreated resource uses a new ID. |
| Trash or permanent deletion | Exclude from search and preserve the token. Show a neutral unavailable label; when safe, authenticated owner UI can explain a confirmed deletion. Distinguish known deletion from an unknown ID only within authorized policy. |
| Disabled, uninstalled or offline module | Keep the token, offer retry when meaningful, and resolve again after recovery. An intentional reinstall follows existing identity reuse rules. |
| Forbidden, revoked or existence-sensitive | Neutral unavailable label, no cached label, preview, existence confirmation or navigation. |
| Resource merge, reparenting across identities, or cross-module move | Keep the old token. Any future alias needs explicit owner policy, current authorization for both ends, bounded redirect traversal, cycle handling and provenance. Never guess a match by name or silently rewrite the token. |

Internal resolver results such as `forbidden`, `not_found`, `deleted` and `temporarily_unavailable` remain distinct where applicable. Wire v1 lacks first-class trashed and redirected states. Use privacy-safe fallbacks until an additive resolver extension is accepted under [REF-ALIASES](https://github.com/Aureate-Empyrean/empyrean-nexus/issues/18).

## Reference picker

Expose the same interaction contract to supported editors via their own adapters. The pilot uses the existing Mnemosyne web editor and AE styling. Future editors may reuse the behaviors and fixtures with their local UI stack.

- Start after an unescaped `$` at a valid text boundary in an editable field. Do not intercept currency such as `$25`, escaped `\$`, code spans/fences or IME composition mid-input. Offer an accessible Insert reference action for touch/assistive use. If a user dismisses, preserve text and caret. Close when the query span becomes invalid.
- An anchored results list on desktop or a touch-friendly panel on small screens shows module, type and title. Keep focus anchored to editing or return it on dismiss/selection. Announce loading, result counts and errors through the accessible status channel. Arrow keys move active selection, Enter selects, Escape dismisses, Tab keeps ordinary focus navigation. Touch targets support scrolling and tap selection.
- Replace exactly the active query span with one reference in one undo step after explicit selection. Fence stale selection against changed text, caret, revision, response generation and revoked scope. Selection does not navigate; activation in rendered preview opens the target and uses standard leave guards. The user can continue editing around the reference, remove it, or choose a replacement.
- Browser fixtures cover multi-provider and same-name rows, delayed and out-of-order responses, literal dollars and IME, empty/partial states, keyboard and touch, copy/paste, undo/redo, reload, rename, conflict recovery, restore, revocation, disabled providers and exact navigation. Use synthetic data.

## Adoption and open decisions

1. Accept and integrate the contract. Confirm delivery scope (V1 or later) and provider disclosure rules. Broad keyword or semantic content search and create-target are separate decisions on the existing Issues. Review initially proposed titles and resource types, and keep richer previews off by default.
2. Nexus establishes bounded scoped coordination and exact opens. Meridian enables Person references for the Mnemosyne pilot after its existing handoff is cleared. Use synthetic providers for contract and coordination tests.
3. With the Nexus and Meridian pilot surfaces integrated, Mnemosyne ships the note-body use case as the first editor adapter and verifies the authenticated round trip. Chronos can reuse its query code while preserving the legacy Meridian path. Lyra, Argus and Atlas add opt-in providers after their relevant base and ownership gates.
4. Initial provider candidates are Meridian Persons, Chronos owned Events with stable identities, Lyra saved Movies/Series, Argus owned Photos and Atlas saved Places. Lyra seasons/episodes and Atlas Areas/Routes need their existing exact-route and domain prerequisites. Janus and private development tooling are outside this capability, including existence and backlink search. Future Abundantia can opt in with its own owner-approved types, redaction, identity and exact scopes through the same contract; its product scope and implementation are separate.

Implementation plans must preserve the existing Nexus navigation/auth/SDK hold, Meridian and Atlas external handoff, and Chronos/Lyra/Argus candidate ancestry. Provider-specific starts depend on live acceptance and approvals, not on this proposal's publication. Review contract fixtures before any implementation: two equal labels with distinct IDs; mixed-owner or malformed results; denied and revoked scopes with no cache leak; failed providers; and a saved note surviving a rename, restore and index retry. Verify the old Meridian link flow separately. Preserve the dirty architecture worktree and reconcile its pending ADR 0029 documentation during its own handoff.
